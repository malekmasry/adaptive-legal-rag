# v230 versus v229

This branch starts directly from Moonvolk's benchmark commit `f19a327`. It keeps the existing platform proxy, role-restricted services, pinned BGE code and unchanged two-order DeepSeek judge. The added entry point is `run_v230.py`.

The product and final submission are on `codex/v230`. Its source commit is `e982d357a4ceab21105aa62cda577bb7aa7d918c`; the results commit is `94a947c`. Final submission SHA256: `92fcd1460ccf4d92ded8150df05d0026182af40b6b575c8b6e787f6d805f5982`.

Read `reports/v230-v229/report.txt` and `results.json` for all questions, answers and votes. `artifacts/v230-v229-AUDIT.zip` contains original frozen inputs, run packages, runtime diagnostics, judge responses, finalization proof/replay, source snapshots and a SHA256 manifest. It is a research archive, not the platform submission. API credentials, model weights and embedding databases are excluded.

## Design and result

- Old 20 development questions: identical original baseline. v229 scores 75.0625; v230 scores 75.5. Only one per-question score changed; 14 final answer strings are identical.
- Old 12 subject questions: direct v230-versus-v229 comparison, 11 ties and one judge validation error excluded.
- New 20 compound/paraphrased questions: direct comparison, 1 win, 1 loss and 18 ties. They were frozen before paid generation, but were used in offline implementation checks and are development data.
- 10 regression questions: correct core conclusions under manual source review; no fabricated LLM-judge score is assigned.

These different baseline scales must not be pooled. No robust quality improvement or hidden-platform score prediction is established. The user-reported official v229 reference is 35.5/100 in 258 seconds; v230 has not been submitted.

The full run generated 62 v230 and 20 fresh v229 answers with zero runtime/API errors. The final product adds only pure output formatting after completed review. All 62 outputs were replayed; 2 changed and were judged in both orders again, while all other text and corresponding votes were preserved. Original and final records are kept separately. This is not a second full live run of the final ZIP.

65 product tests and 16 benchmark tests pass. Total usage including finalization: DeepSeek 209 calls / 1,382,427 reported tokens; Qwen 20 calls / 591,563 input tokens. Qwen role is restricted to Qwen/Qwen3-Reranker-8B at the separate endpoint. Generator and judge use DeepSeek at the user's endpoint.

## Reproduction

`python benchmarks/platform_proxy/run_v230.py --help` lists the required paths. A fresh run requires a compatible frozen v229 parent run, private service configuration, pinned BGE weights, the embedding warm seed, candidate ZIP and runtime source directory. The older v229 audit is in `codex/benchmark-v229`. Do not place keys in tracked files.

The recorded original candidate is `run-packages/v230-generation.zip` inside this audit. Its hash is `bc09ede75f1d9752c451ec6741ef62a8631961d05a8a4a54ae109bb0ec984f44`. The final candidate is the audit's top-level `v230.zip`; do not substitute it into an existing frozen run directory. A new full generation uses a new output directory and will naturally produce a new measurement.

`audit-tools/finalize_v230.py` is the exact executed output-replay script, with recorded local paths; it is retained as evidence rather than advertised as a portable command. `finalization/freeze.json` proves the runtime difference, and `finalization/replay.json` records every preserved/changed answer hash.

The original experiment took 1046.391 seconds, plus 48.953 seconds for finalization. Four separate v230 runtime batches sum to 451.953 seconds. Exact Qwen caching and shared three-call concurrency mean these are not controlled standalone latency measurements or platform runtime predictions.
