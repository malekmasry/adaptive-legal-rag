# Приближённый LLM-бенчмарк ПСБ, 15 ноября 2026

**Текущий запрос — stress20.** Первоначальный пилот на восьми вопросах остановлен
при расширении задачи. Его завершённые controls, baseline и допустимые оценки
conditional35 сохранены и переиспользуются по точному совпадению входов.
Оплаченные вызовы родительского пилота учитываются в общем журнале расходов.

## Стрессовый прогон на 20 вопросах

`prepare_stress.py` фиксирует 20 явно перечисленных сложных development-вопросов
до новых ответов. Включены парные даты действия допсоглашения, регламента и письма,
расчёт с гипотетическими числами, отрицание, похожие контрагенты, исключения,
несколько подвопросов, отсутствие нормы, ложная история и инструкция в базе.
В `selection_rationale` сохранено, почему выбран каждый случай. Набор специально
смещён к слабым местам; его результат нельзя называть средним качеством продукта.

Сравниваются сохранённые ответы conditional35 и **новые реальные ответы** двух
неизменённых ZIP: v8 и hybrid35v8, по 20 на каждый. Их SHA-256 проверяются до
распаковки. Данные golden и настоящие API-ключи не попадают в каталоги продуктов.
Локальный шлюз разрешает `/chat/completions` только DeepSeek, `/rerank` только
Qwen3-Reranker-8B, а `/embeddings` обслуживает локально настоящим BGE-M3 закреплённой
ревизии с проверенными сохранёнными векторами. Новые векторы считаются на CPU.

У v8 остаётся TOP_K=40, у гибрида TOP_K=12; температура 0, MAX_TOKENS=8192,
дедлайн продукта 1100 с и внешний предел 1200 с. Обе версии запускаются параллельно
с MAX_WORKERS=3 каждая и тремя общими внешними API-слотами. Время этого режима
не является замером производительности на платформе; оно включает конкуренцию
двух запусков и возможный локальный расчёт недостающих эмбеддингов.

Предел stress20, включая родительский пилот: 320 DeepSeek-вызовов,
110 Qwen-rerank-вызовов и консервативный chat-предел в 6 млн единиц
(UTF-8-байты запросов плюс максимальные выходные токены). Это верхняя оценка,
а не фактический расход; реальные usage приводятся в отчёте.

```text
python -m unittest discover -s benchmarks/platform_proxy -p "test_*.py" -v
python benchmarks/platform_proxy/prepare_stress.py --source /path/psb_v2 --consolidated /path/consolidated --output /path/private-stress20 --releases /path/release-zips --parent /path/private-eight-case-pilot
python benchmarks/platform_proxy/run_stress.py --run /path/private-stress20 --services /path/private-services.json --weights /path/bge-weights --seed /path/seed_embeddings --pilot /path/consolidated/pilot
```

Исторические ответы conditional35 получены в другом запуске и при другом
подключении; их использование экономит расходы, но не делает сравнение полностью
контролируемым. Нужен отдельный одинаковый повтор всех версий для такого вывода.
Файлы `runtime.json`, `all-answers.json` и `answer-snapshot.json` сохраняют новые
ответы и происхождение; судейство начинается только после сохранения ответов.

## Исходная постановка пилота

Продолжение `f19a327` Мунволка с отдельным новым экспериментом. Его приватный
набор v8 на 72 вопроса, controls и часть ZIP недоступны. `v8_deepseek/` сохранён
без изменений: этот эксперимент не выдаётся за запуск той поставки.

Проверяем гипотезу, что короткий LLM-судейский промпт с эталоном лучше отражает
проверку платформы, чем сложная проверка графа доказательств. Это гипотеза;
промпт, baseline и скрытые вопросы ПСБ неизвестны. Исторические баллы не являются
целевыми значениями, к которым подгоняется локальная оценка.

## Что взято из регламента и FAQ

- Судья сравнивает ответ команды с baseline, ориентируясь на golden.
- Два порядка: baseline/A и кандидат/B, затем наоборот.
- Оценки 0, 0.25, 0.5, 0.75, 1; среднее двух раундов.
- Выдуманный факт обнуляет вопрос. Здесь явно выбрана консервативная трактовка:
  достаточно подтверждённого судьёй флага в одном раунде. Точное правило слияния
  таких флагов платформой неизвестно.
- `100 × (0.7 MR + 0.3 WR)`, WR исключает ничьи; все ничьи дают WR=0.5.
- Техническая ошибка судьи остаётся пропуском, а не нулём или ничьей. Сравнение
  систем дополнительно показывается на общих успешно оценённых вопросах.
- Уточнение вместо ответа на самодостаточный вопрос — недостаточный ответ.
- Верные дополнительные сведения вне golden не штрафуются. Длина и время
  исполнения сами по себе не являются критерием качества.

Решения о качестве, ошибках, преимуществах и неподтверждённых фактах принимает
DeepSeek. Python проверяет JSON, принадлежность цитаты ответу и считает формулу.
Он не выставляет качество по ключевым словам или регулярным выражениям.

## Два результата одного судейства

`psb_rule_proxy` использует краткий промпт по опубликованным правилам. У судьи нет
полного корпуса, поэтому он обязан отличать явное противоречие от непроверенного
дополнительного факта. Его семантические решения всё равно могут быть ошибочными.

`literal_gold_stress` дополнительно обнуляет вопрос, если LLM отметила
неподтверждённые дополнительные сведения. Это намеренно грубая проверка
чувствительности к сравнению с эталоном, **противоречащая FAQ при верных
дополнительных фактах**. Это не второй официальный скор и не утверждение о том,
что реальный судья ПСБ работает именно так. Дополнительные вызовы модели для
этого диагностического показателя не требуются.

## Пилот и происхождение

Берутся восемь ранее использованных вопросов, на которых сохранились реальные
ответы пяти систем: vector14, coverage2257, review29, conditional35 и v8.
Вопросы сопоставляются точно, а не нечётким поиском. Прежние Qwen-оценки не
переиспользуются. Новые решения судьи — только DeepSeek.

Общий baseline создаётся один раз: лексические top64 из conditional35 →
Qwen3-Reranker-8B top6 → краткий ответ DeepSeek. Baseline не получает golden.
Он не является неизвестным baseline ПСБ. Никаких новых эмбеддингов по удалённым
API здесь нет; для выбранного простого baseline используется лексический поиск.

Восемь случаев были ранее выбраны для диагностики. Это не репрезентативный тест
всей платформы, не независимый holdout и не доказательство воспроизведения 12.5
или 35 баллов. Исторические локальные ответы также не совпадают с неизвестными
ответами тех же решений на скрытых вопросах платформы.

## Изоляция и расходы

`services.py` допускает только:

| Роль | Модель | Подключение |
|---|---|---|
| GENERATOR | deepseek-v4.1-flash | пользовательский API |
| JUDGE | deepseek-v4.1-flash | тот же пользовательский API |
| RERANKER | Qwen/Qwen3-Reranker-8B | отдельный API и ключ |

Вызов Qwen через DeepSeek API, судейство через Qwen API, смена модели и редирект
блокируются. Конфигурация не попадает в Git или отчёты. Локально хранится её
отпечаток; продолжение под другой конфигурацией требует отдельного эксперимента.

Предел пилота: 100 chat-вызовов, 8 rerank-вызовов и консервативный предел chat
в 1 000 000 единиц (UTF-8-байты запроса плюс максимальные выходные токены).
Это верхняя оценка токенов, не обещание фактического расхода или стоимости.
Бюджет записывается ДО HTTP-запроса и сохраняется после перезапуска. Ответы и
ошибки кэшируются; автоматического повторного расхода на ошибочные запросы нет.
Фактические usage и Qwen meta сохраняются отдельно. После провала controls
генерация baseline и массовое судейство не запускаются.

## Запуск

Приватная конфигурация содержит отдельные `GENERATOR_*`, `JUDGE_*`, `RERANKER_*`
поля MODEL, BASE_URL, API_KEY; пример схемы — в соседнем `v8_deepseek/`.
Каталог эксперимента и конфигурация должны оставаться вне публичного репозитория.

```text
python -m unittest discover -s benchmarks/platform_proxy -p test_proxy.py -v
python benchmarks/platform_proxy/prepare.py --source /path/psb_v2 --consolidated /path/consolidated --output /path/private-new-run
python benchmarks/platform_proxy/run.py --run /path/private-new-run --services /path/private-services.json
```

`prepare.py` фиксирует входы и код ДО модели. Любые изменения после этого
отклоняются. `run.py` сначала проверяет четыре синтетических контроля: одинаковые
ответы, неверное число, ненужное уточнение и правильный ответ против неправильного.
Они проверяют базовую работоспособность судьи, не калибровку по баллам платформы.

Отчёты: `controls-result.json`, `baseline.json`, `judgments.json`, `summary.json`,
`calls.jsonl`. Не публикуйте эти файлы автоматически: они могут содержать
приватные вопросы и ответы. Сводка показывает известные платформенные баллы
только после судейства, диагностическую ранговую корреляцию, покрытие,
неустойчивость порядка A/B и расход. Близкое число на таком пилоте не означает
эквивалентности реальной проверке ПСБ.
