# PSB RAG Benchmark — v8.1-deepseek-20261115

В этой версии **DeepSeek используется и как генератор ответов, и как судья**. Qwen используется только для переупорядочивания найденных фрагментов — reranking.

| Роль | Переменная модели | Значение |
|---|---|---|
| Генератор ответов RAG | `GENERATOR_MODEL` | `deepseek-v4.1-flash` |
| Судья бенчмарка | `JUDGE_MODEL` | `deepseek-v4.1-flash` |
| Reranker | `RERANKER_MODEL` | `Qwen/Qwen3-Reranker-8B` |

Генератор отвечает на вопрос по найденным документам. Судья отдельно оценивает готовый ответ по разметке. Одинаковое имя модели не объединяет эти роли: у каждой собственные запросы и явные настройки подключения.

**Статус поставки:** тесты, калибровка и модельные API при подготовке этой версии не запускались. Вызовов моделей: **0**. Статус `PASS` для новой версии не заявляется. Приведённые ниже команды калибровки и development предназначены для последующего запуска пользователем; они обращаются к модельным API.

## Что находится в Git

Публичная поставка содержит код движка в `engine/`, сборщик `prepare.py` и эту инструкцию. Архив корпуса, приватные вопросы и gold-разметка, ключи, приватная конфигурация сервисов и старые outputs в Git не включаются.

Для запуска нужен локальный исходный каталог прежнего бенчмарка с приватными входными данными. `prepare.py` переносит необходимые приватные входы **побайтно локально**, создаёт отдельный каталог новой версии и использует новый код движка. Это не публикация входных данных и не повторное использование старых ответов или оценок.

## 1. Подготовить приватную конфигурацию

Создайте `services.private.json` вне публичного репозитория. У каждой роли явно указываются собственные `*_BASE_URL`, `*_API_KEY` и `*_MODEL`. Не рассчитывайте на подстановку настроек генератора для судьи. Даже если роли обслуживает один шлюз, заполните оба набора полей.

Шаблон ниже содержит только обозначения; замените их своими значениями локально:

```json
{
  "GENERATOR_BASE_URL": "<GENERATOR_BASE_URL>",
  "GENERATOR_API_KEY": "<GENERATOR_API_KEY>",
  "GENERATOR_MODEL": "deepseek-v4.1-flash",
  "JUDGE_BASE_URL": "<JUDGE_BASE_URL>",
  "JUDGE_API_KEY": "<JUDGE_API_KEY>",
  "JUDGE_MODEL": "deepseek-v4.1-flash",
  "RERANKER_BASE_URL": "<RERANKER_BASE_URL>",
  "RERANKER_API_KEY": "<RERANKER_API_KEY>",
  "RERANKER_MODEL": "Qwen/Qwen3-Reranker-8B"
}
```

Внутри RAG runtime настройки генератора передаются через совместимые имена `LLM_BASE_URL`, `LLM_API_KEY`, `LLM_MODEL`. Это внутренние aliases для роли `GENERATOR`, а не ещё одна модель и не настройки судьи. Настройки `JUDGE_*` относятся только к оцениванию. Не подменяйте `JUDGE_MODEL` именем reranker.

Локальные эмбеддинги используют подготовленные веса закреплённой ревизии BGE-M3. Путь к этим весам потребуется для development-прогона; веса не входят в Git.

## 2. Собрать отдельный локальный запуск

Из каталога этой публичной поставки:

```sh
python prepare.py \
  --source-benchmark "/path/old/benchmark" \
  --services "/path/services.private.json" \
  --output "/path/new-run"
```

Выберите новый каталог `/path/new-run` вне публичного репозитория. После подготовки команды запуска используют `/path/new-run/benchmark/` и приватную конфигурацию `/path/new-run/services.private.json`.

**Этот шаг только собирает локальные файлы и конфигурацию. Он не запускает тесты, генерацию, судью или модельные API.** Исходный каталог прежнего бенчмарка сохраняйте отдельно от нового запуска.

## 3. Выполнить новую калибровку судьи

Следующий шаг выполняется отдельно, когда разрешён запуск модельных API:

```sh
python "/path/new-run/benchmark/v8_run.py" \
  --stage calibrate \
  --services "/path/new-run/services.private.json"
```

Калибровка должна быть выполнена заново для судьи `deepseek-v4.1-flash`. Старый результат калибровки Qwen её не заменяет. Перед development-прогоном проверьте отчёт новой калибровки и выполнение предусмотренных протоколом условий допуска; сам факт завершения команды ещё не означает успешную калибровку.

## 4. Запустить development после новой калибровки

Только после успешной новой калибровки:

```sh
python "/path/new-run/benchmark/v8_run.py" \
  --dataset development \
  --stage all \
  --services "/path/new-run/services.private.json" \
  --weights "/path/to/pinned/bge-m3/5617a9f61b028005a4858fdac845db406aefb181"
```

`--dataset development` указан явно, чтобы не перепутать наборы. `--stage all` запускает предусмотренные движком стадии development-прогона. Веса должны соответствовать закреплённой ревизии и её manifest.

**Holdout сейчас не запускать.** В этой инструкции нет команды его запуска. Его дальнейшее использование требует отдельного решения после выбора кандидата и фиксации протокола.

## Как читать новые результаты

Идентификатор судейской версии: **`v8.1-deepseek-20261115`**. Это новая линия оценивания, потому что модель судьи изменена.

- Не объединяйте старые Qwen-оценки и новые DeepSeek-оценки в одну таблицу как результаты одного неизменного судьи.
- Разницу между старым и новым баллом нельзя приписывать только изменению RAG: изменилась и процедура модельного оценивания.
- Для сравнения RAG-систем используйте одинаковую новую версию судьи, разметку, условия запуска и правила агрегации.
- Храните старые прогоны отдельно. Новые отчёты и приватные данные остаются в локальном каталоге запуска, вне Git.

Пока новая калибровка и development не выполнены, эта поставка означает готовность к их запуску, а не подтверждённое качество или успешное прохождение бенчмарка.
