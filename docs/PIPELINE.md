# Адаптивный пайплайн и строгий IRAC

Основа — наш лексический поиск без векторов. Веса генератора не обучаются:
реализуется поиск, подготовка и проверка ответа поверх настроенного API.
База передаётся при запуске. `solution.py` и `pipeline_cli.py` используют
один `LegalAssistant.answer`.

## Путь вопроса

1. TXT/MD/DOCX читаются из ZIP без извлечения путей на диск. Ограничены число файлов,
   распакованный объём и XML DOCX. Дубли путей отклоняются. Пропущенные пустые или
   нечитаемые документы отражаются в диагностике. Фрагменты сохраняют ID, документ,
   пункт и смещения в оригинале.
2. Базовый поиск учитывает слова, формы слов, триграммы, номера договоров и
   контрагентов из текста документов; формы имён компаний нормализуются в точном
   поиске сущностей. Тематического словаря под тестовые вопросы
   нет; имена файлов не дают прибавку за договор или компанию. `USE_EMBEDDINGS=0`
   по умолчанию, CLI явно отключает эмбеддинги.
3. Контекст ограничивается по объёму. Убираются дубли внутри документа, добавляются
   соседние продолжения и ограниченно разрешаются явные ссылки на номера пунктов.
   Номер пункта разрешается внутри документа либо документов с явной однозначной
   связью. Связи берутся из ссылок на номера договоров, заголовки и редакции,
   а не из знакомых названий и годов. Две датированные редакции сами по себе
   не устанавливают замену одной другой. Краткое название документа сопоставляется
   с заголовком без реквизитов организации; указанная дата редакции выбирает
   однозначный документ. Явно названный пункт сохраняется в связи и получает
   приоритет при укладке контекста. Это адресный поиск оснований.
4. Планировщик выделяет подвопросы и извлекает граф фактов из источников ДО ответа.
   Факт содержит точную цитату, ID источника, субъект, отношение, объект и условия.
   Выдуманные ID и цитаты не допускаются. При конкретном пробеле выполняется
   дополнительный поиск: по умолчанию один проход, максимум два запроса.
5. Генератор получает вопрос, граф, оригинальные фрагменты фактов и метаданные
   сторон, редакций и договоров. Возвращает JSON с утверждениями для R, A и C,
   вопросом I, пробелами и статусом. Ссылки в итоговый текст добавляет код.
6. Отдельный вызов модели проверяет смысл каждого утверждения, полноту, условия,
   ложные предпосылки, противоречия и обоснованность уточнения/отказа. Он независимо
   извлекает граф из текста ответа и перечисляет все факты, необходимые для вывода.
   Недостающие подтверждённые ссылки добавляются до выдачи.
7. Арбитр сочетает проверку модели с проверками кода. При ошибке выполняется одна
   попытка исправления с исходным черновиком и конкретными замечаниями. Поиск,
   вызовы и время ограничены. Непроверенный ответ не выдаётся как подтверждённый.
8. Статический рендерер формирует **I — Вопрос, R — Нормы, A — Применение,
   C — Вывод**. Технический ответ, частичный ответ и уточнение имеют ту же структуру.
   Предмет и область действия документа должны подтверждаться найденными
   фрагментами, как и другие факты. Фиксированного «пункта с предметом» нет.

## HalluGraph

`hallugraph.py` — адаптация идеи графового сопоставления, а не воспроизведение
реализации с spaCy и отдельной SLM. Источник метода:
[HalluGraph, Noël et al.](https://arxiv.org/html/2512.01659v1).

Сохраняются граф источников, независимо извлечённый граф ответа и ссылки на цитаты.
`entity_grounding` и `relation_preservation` измеряют буквальное совпадение
нормализованных концов и названий отношений. Пустой граф даёт `null`, не 100%.
Несовпадение фраз само по себе не блокирует правильное применение условной нормы.
`semantic_relation_preservation` отдельно показывает долю утверждений с явным
подтверждающим набором фактов по оценке проверяющего. Это оценка модели, не
вероятность истинности и не результат калибровки на датасете статьи.

Дополнительно код проверяет неизвестные числа, номера договоров, цитируемые имена,
явную перестановку направления одинаковой связи, некоторые смены отрицания,
переход от исключающей даты к включающей и явные календарные сравнения.
Нормализуются даты, разряды чисел и распространённые числительные.
Названия контрагентов сопоставляются с ограниченной нормализацией русских
падежных окончаний; похожие «Альфа-Трейд» и «Альфа-Трейдинг» остаются разными.
Дата редакции, начало действия и исключающая дата окончания хранятся раздельно. Неоднозначные
обстоятельства и полнота смыслового вывода всё ещё требуют проверки моделью.

## Граница доверия

`rag_safety.py` задаёт правила роли. Документы, названия, история, планы, черновики
и проверки передаются как JSON-данные, не как системные инструкции. Подозрительные
строки и известные форматы ключей фильтруются перед моделью; оригиналы сохраняются.
Эвристический фильтр не считается полной защитой. Модель не получает инструменты
запуска кода, браузера, файлов или почты. Её поисковые предложения могут только
вызвать ограниченный локальный поиск. Адреса API задаются оператором, а не моделью;
перенаправления HTTP отключены.

JSON разбирается без `eval`, с ограничениями размера/типов, запретом повторных
ключей и нечисловых констант. Неполные ответы API, неверные ссылки и неполные
вердикты не принимаются молча. Вывод не превращается в HTML или исполняемые ссылки.
Отдельный сервер реранкера требует отдельный ключ: ключ генератора туда не
пересылается автоматически. Реранкер по умолчанию отключён.

Это несколько уровней защиты от prompt injection, не гарантия против всех атак.
Подложная правовая норма в корпусе не равна инструкции для ИИ: подлинность базы
остаётся ответственностью поставщика документов.

## Измерения

`rag_telemetry.py` изолирует запросы через ContextVar. Диагностика содержит время
поиска, поиска ссылок/соседей, подготовки контекста, модельных этапов, полный
elapsed time, HTTP-попытки и usage шлюза. Денежная стоимость не вычисляется без
тарифа. При параллельном CSV суммы времени запросов не равны времени пакета.

`MAX_PIPELINE_CALLS` ограничивает логические вызовы; HTTP-повторы учитываются
отдельно. Бюджет времени проверяется между вызовами и ограничивает HTTP timeout,
но не является жёстким realtime deadline для каждой сетевой фазы.

Проверяющий сейчас использует тот же настроенный генератор отдельным вызовом;
общие ошибки модели остаются возможны. Старые 54 вопроса теперь регрессионные,
а не независимый holdout. Старые численные оценки относятся только к сохранённым
снимкам кода. После удаления привязок к корпусу полный платный прогон не
повторялся; локальные проверки не доказывают качество LLM на другой базе.
На новых 25 вопросах начальное покрытие выросло с 23/25 до 25/25 после общей
нормализации имён, но это регрессия на известном наборе, не независимая оценка.

## Файлы

- `legal_core.py`: база, исходный retriever, прокси, единый вход и CSV.
- `adaptive_pipeline.py`: доказательства, план, IRAC, проверки и арбитр.
- `hallugraph.py`: графы, цитаты, числа, договоры и календарные границы.
- `rag_safety.py`: правила, фильтрация данных и разбор структуры.
- `rag_telemetry.py`: измерения одного запроса.
- `pipeline_cli.py`: запуск отдельного вопроса из командной строки.
- `solution.py`: точка входа для пакетной проверки.
- `experiments/evaluate_frozen_retrieval.py`: локальная проверка фиксированных
  вопросов на заранее размеченных фрагментах.
- `reports/adaptive_rag_history.ipynb`: история сравнений с таблицами и графиками.
