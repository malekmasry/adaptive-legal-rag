СРАВНЕНИЕ BM25 И РУССКОГО СТЕММИНГА

База кода: 5bc69ff (вариант с официальным результатом 15,8).
Этот эксперимент оценивает только поиск. Официальный балл и качество ответов не измерялись.
Нет вызовов API, эмбеддингов, реранкера, расширения по связям или генератора.

МЕТОДИКА
Использованы 54 прежних вопроса и 25 дополнительных: всего 79.
Один вопрос без ответа в базе (ID 3) исключён из метрик поиска; знаменатель — 78.
База: 21 документ, 342 фрагмента. Архив документов совпадает с прежним по SHA256.
Для 21 вопроса вручную проверены основания после изменения нарезки с 312 до 342 фрагментов.
Остальные основания перенесены по точному совпадению пути и текста.
Обновлённый эталон зафиксирован до запуска сравнения. Это аудит ассистентом, не независимая экспертиза.
Часть прежних вопросов уже использовалась при разработке: это регрессионный набор, не независимый тест площадки.

В двух вариантах обычного BM25 текст индекса одинаков: документ, номер договора, стороны, родительский раздел, текст.
Различие: исходные токены против основ слов. BM25: k1=1.2, b=0.75; без триграмм и специальных бонусов.
В двух вариантах текущего поиска изменяется только обработка слов в search_terms().
Оригинальные токены сохраняются, ручное обрезание окончаний заменяется основами Snowball.
Триграммы, веса полей, бонусы за договор/организацию, разбор диалогового запроса одинаковы.

ВЫВОД
Стемминг заметно помогает обычному BM25. В текущем поиске прирост полного покрытия топ-12 небольшой и есть два ухудшения.
Для пула из 64 кандидатов текущий поиск улучшился с 77/78 до 78/78.
Это даёт основание для следующего отдельного испытания, но не доказывает рост балла после реранкинга и генерации.
Режим библиотеки включается через LEXICAL_STEMMER=snowball.
В опубликованной dev_bm25_test_v1 точка входа solution.py явно включает snowball и отключает эмбеддинги.
Реранкер на площадке используется при наличии его конфигурации; в данном локальном сравнении он не запускался.
