Эксперимент chunk-boundaries-fix
Основа: dev_if_test, 5d7f10d (сообщённый результат 35/100).

Изменение
Только векторная ветка использует новые фрагменты. Исходный запрос сначала
проходит прежние BM25 и реранкер. При оценке < 0,5 выдача заменяется отдельно
ранжированной векторной. Мультизапрос и новый стеммер сюда не входят.

Нарезка structural_chunking.py
- Сохраняет целые строки/абзацы источника. Лимит 1400 символов мягкий;
  длинный абзац не разрезается посреди суммы, условия или предложения.
- Отличает заголовок «Статья N. ...» от сообщения об изменении статьи.
- Выделяет пункты и подпункты закона, сохраняет вводные условия списков.
  Пункты 1.1, 1.2, 1.8-1 не становятся детьми пункта 1 из-за записи номера.
- Объединяет короткие пункты корпоративного раздела с его заголовком;
  отдельные чанки только из названия раздела не создаются.
- Контекст берётся из исходного текста. Сохраняются его смещения, редакция
  корпоративного документа, точные диапазоны и соответствующие старые ID.
- Очистка инструкции ИИ в записке применяется к тексту для моделей;
  оригинал для проверки смещений остаётся неизменным.

Подключение
solution.py явно задаёт DENSE_CHUNKING=structural вместе с условным режимом
и включёнными эмбеддингами. При прямом импорте ядра по умолчанию legacy —
это позволяет воспроизводить исходный контрольный вариант.
BM25, его ID, записи источников, search_texts, порог и генерационный промпт
остались прежними. Новые ID начинаются после лексических; by_document для
лексической ветки не меняется. Для векторной ветки есть отдельная коллекция.
Новые фрагменты передаются эмбеддеру, векторному реранкеру и генератору.
Сбой векторной ветки сохраняет уже ранжированные исходные BM25-фрагменты.
Индекс документов строится при запуске один раз. Старые векторы не переиспользуются.

Ограничения
Это детерминированный структурный парсер, не полная юридическая интерпретация.
Он не восстанавливает отсутствующие нормы, не разрешает все межстатейные
ссылки и не доказывает применимость каждого исключения.
Бюджет контекста 18000 символов и пул реранкера 64 сохранены. Из-за изменения
размеров фрагментов в контекст может поместиться другое число оснований.
Онлайн-качество, калибровка оценок реранкера на новых фрагментах и время
полного прогона ещё не измерены. Рост качества или ускорение не заявляются.
Старый кэш BGE-M3 на 312 фрагментов для этой сборки непригоден.

Тесты
tests/test_structural_chunking.py: границы, условия согласия/ставок, заметки
о редакциях, точные цитаты, очистка инструкции, неизменность BM25,
векторизация новых текстов и возврат к BM25 при ошибке реранкера.
Также проверяются прежние conditional/single_pass и реальный ZIP entry point
через локальный HTTP-сервер, включая обе ветки и принудительную активацию
новой нарезки вопреки переменным родительского окружения.
Проверки выполняются без обращений к моделям организаторов.
